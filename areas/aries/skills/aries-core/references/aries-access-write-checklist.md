# ARIES Access Write Checklist

Use this checklist as the contract for any code path that writes table data to an ARIES `.accdb` or `.mdb`.

Routine table population must go through the canonical `AriesAccessWriter` implementation. Raw SQL `execute` calls are for diagnostics or explicitly approved one-off edits only.

## Connection

- Copy the template database and write into the copy.
- Never drop or recreate ARIES core tables.
- Match Python bitness to the installed Microsoft Access ODBC driver.
- Configure ODBC decoding exactly:
  - `SQL_CHAR`: `latin-1`
  - `SQL_WCHAR`: `latin-1`
  - `SQL_WMETADATA`: `utf-16-le`
  - connection encoding: `utf-8`

## Column Matching

- Read target columns with `SELECT * FROM [table] WHERE 1=0` and `cursor.description`.
- Strip embedded NUL characters from Access metadata names.
- Use ODBC catalog metadata only for type/nullability coercion checks.
- Report matched and unmatched source columns in the run summary.

## Inserts

- Never omit a required non-null Access field such as `AC_PROPERTY.DBSKEY`.
- Convert empty strings to `NULL` before insert.
- Coerce dates, numeric values, and text length to the target Access column schema.
- Add governed extension columns only through `ensure_columns`.

## Delete Scope

- Fresh template exports must be idempotent and must not retain sample/template source rows.
- Clear generated data tables before insert unless a table is explicitly additive.
- `AC_SETUPDATA` is additive: preserve template setup rows and replace only generated `SECNAME` sections.
- `AC_SETUP` is template-governed and should be preserved unless a human explicitly approves an edit.
- Project tables must reflect only the generated project universe:
  - `PROJECT`
  - `PROJLIST`
  - `SORTFILTERS`
  - `SelFilters`
- Stale source-data tables from populated templates must be cleared when they are not generated by the exporter:
  - `AC_FCST`
  - `AC_MONTHLY`
  - `AC_RESERVES`
  - `AC_WELL`
  - related obsolete/source tables listed in the writer.

## Governance Reads

- Do not hardcode master/display behavior when it can be read from the database.
- Prefer `TBLSETS`, `ARSYSTBL`, and `DBSLIST` for template governance.
- Append generated display/provenance columns such as `SRC_DB` to `DBSLIST.SHOWIDS` when a matching `DBSKEY` row exists.

## Post-Write Integrity Gates

Fail the write if any of these checks fail:

- `AC_ECONOMIC.PROPNUM` is not in `AC_PROPERTY.PROPNUM`.
- `AC_PRODUCT.PROPNUM` is not in `AC_PROPERTY.PROPNUM`.
- `AC_TEST.PROPNUM` is not in `AC_PROPERTY.PROPNUM`.
- `AC_DAILY.PROPNUM` is not in `AC_PROPERTY.PROPNUM`.
- `AC_OWNER.PROPNUM` is not in `AC_PROPERTY.PROPNUM`.
- `PROJLIST.PROPKEY` references a property not present in `AC_PROPERTY.PROPNUM`.
- Nonblank `AC_ECONOMIC.QUALIFIER` values are not selectable by `AC_SCENARIO` for that section.
- Final row counts for generated replacement tables do not equal build counts.

## Run Summary

Every Access write should return or persist:

- per-table before, inserted, and after counts
- matched and unmatched columns
- added columns
- warnings
- orphan counts
- scenario qualifier integrity results
- pass/fail status
